# KPanel 轻量文件管理设计

- 状态：已实现，L2 验收通过，待发布授权
- 基线：`v0.29.0` / `2abef3d`
- 核验等级：L2（跨 Panel、Agent 与宿主机文件写入）

## 1. 业务定位

文件管理是 KPanel 对宿主机 `/home` 的日常文件工作台，入口位于左侧“体检”上方。
它服务于网站文件、应用数据、备份和普通用户目录，不替代 SSH，也不接受任意宿主机路径。

产品原则：

- 已登录管理员可以管理 `/home` 下的普通文件，不以“是否由 KPanel 创建”限制操作。
- KPanel 自身运行目录、凭据和任务状态始终隐藏且不可读写。
- 默认使用专业列表视图；目录快捷入口、批量选择、右键菜单和快速预览保持一屏可用。
- 大文件传输采用流式代理，不把完整内容载入 Panel 或 Agent 内存。
- 写入后重新读取真实文件状态，不维护第二套文件事实。

## 2. 首版范围

### 文件操作

- 浏览目录、搜索当前目录、排序。
- 新建文件夹、上传、下载。
- 重命名、复制、移动、移入回收站。
- 批量复制、移动、下载和移入回收站。
- 查看并修改 POSIX 权限。
- 显示名称、类型、大小、权限、所有者、修改时间和资源版本。

### 查看与编辑

- 文本与代码：纯文本、Shell、Go、JavaScript/TypeScript、Vue、HTML/CSS、JSON、YAML、
  TOML、INI、Nginx、日志、Markdown。
- 图片：PNG、JPEG、GIF、WebP。
- 文档：PDF。
- 媒体：浏览器支持的音频和视频。
- 压缩包及其他二进制：显示元数据并提供下载；首版不在浏览器执行归档内容。
- 编辑器使用懒加载的轻量 textarea + 行号、Tab 缩进、快捷保存和冲突检测，不引入大型 IDE 依赖。

首版不包含在线解压、跨主机传输、Git 客户端、终端或数据库文件解析。这些能力不得通过
任意 Shell 临时补位。

## 3. 信任边界与质量记录

```text
浏览器
  -> Panel Session + Origin + CSRF
  -> Panel 流式代理
  -> Unix Socket + Agent Token
  -> Agent 固定文件动作
  -> /home（排除保护目录）
```

| 项目 | 设计 |
| --- | --- |
| 流量路径 | 浏览器仅访问 Panel；Panel 通过现有 Unix Socket 调用 Agent |
| 不可信输入 | 虚拟路径、文件名、批量来源、目标目录、权限、上传内容、文本内容、Range |
| 权限与可写范围 | 固定根 `/home`；保护 `/home/docker/kpanel`、`/home/docker/kejilion-panel` 和内部回收站 |
| 最坏输入/输出 | JSON 64 KiB；文本编辑 2 MiB；单次上传 512 MiB；列表 500 项；批量 100 项 |
| 最大并发 | 上传 2、下载由 HTTP 服务承载；复制、移动及回收站操作串行执行，目录列表按请求同步且有项目上限 |
| 超时、取消与重试 | 读取随请求取消；上传临时文件失败即清理；写操作不自动重试 |
| 真实状态 | `Lstat`、打开后 `Stat`、目录内容和文件元数据 |
| 失败与回滚 | 上传/编辑使用同目录临时文件、`fsync` 和原子替换；复制失败清理目标临时产物 |
| 性能预算 | 文件页面懒加载；不增加首屏包；流式传输使用固定 64 KiB 缓冲 |
| 网络入侵风险 | 路径穿越、符号链接逃逸、CSRF、超大请求、恶意 MIME、资源耗尽 |

## 4. 路径和隔离

API 使用以 `/` 开头的虚拟路径，`/` 映射到宿主机 `/home`。

每次操作执行：

1. 拒绝 NUL、反斜杠、过长路径、空组件、`.` 和 `..`。
2. 将虚拟路径映射到固定根目录。
3. 对已有路径的每级组件执行 `Lstat`，拒绝跟随符号链接。
4. 检查最终路径不位于保护目录。
5. 打开后再次 `Stat`，避免把链接替换竞态解释为普通文件。

符号链接可以作为目录条目显示，但不可进入、预览、下载、编辑、复制或移动到根外。

## 5. API

Agent 与 Panel 使用相同资源路径，Panel 增加 `/api` 前缀：

```text
GET  /v1/files?path=/docker&limit=200
GET  /v1/files/content?path=/docker/app/file&disposition=inline
GET  /v1/files/content?path=/docker/app/file&disposition=inline&mode=text
PUT  /v1/files/content?path=/docker/app/file
POST /v1/files/upload?path=/docker/app&name=file
POST /v1/files/actions
```

`POST /files/actions` 仅接受固定动作：

```text
mkdir
rename
copy
move
trash
chmod
```

批量操作最多 100 个来源。编辑请求必须携带 `expectedResourceVersion`；资源变化返回 `409`。
批量操作逐项返回成功与失败结果；部分成功使用 `207 Multi-Status`，页面始终重新读取目录，
避免把已完成的文件变更误报为整体失败。
编辑器读取必须显式使用 `mode=text`，Agent 会复核当前大小、UTF-8 编码和 NUL 字节；
图片、PDF 和音视频仍使用 Range 流式读取。

## 6. 前端交互

- 左侧导航：文件位于 Docker 与体检之间。
- 默认列表：目录优先，列出大小、权限、所有者和修改时间。
- 双击目录进入，双击文件打开查看器。
- 右键菜单与顶部/批量工具栏调用同一动作定义，避免能力不一致。
- 代码查看器使用等宽字体、行号和语法类型提示；编辑保存时执行资源版本冲突检查。
- 图片、PDF、音视频通过同源受控 URL 预览；HTML、SVG 等主动内容只按纯文本显示或下载。
- 删除默认进入 KPanel 回收站并明确提示，不在首版提供不可恢复的网页删除入口。

## 7. 验收

- 单元测试：路径穿越、保护目录、符号链接、超限列表/上传/编辑、资源冲突、批量上限。
- Panel 测试：未登录、Origin、CSRF、未知路由、流式响应和 Agent 不可用。
- 前端测试：导航顺序、列表、批量选择、右键菜单、查看器分类和保存冲突。
- 构建：Go 全量测试、前端测试与生产构建、生态规则检查、Linux Agent 构建。
- 人工验收：浅色/深色、桌面/窄屏、上传下载、文本编辑、图片/PDF/媒体预览和失败提示。
