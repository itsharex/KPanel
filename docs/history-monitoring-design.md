# KPanel 轻量历史监控设计

- 状态：30 天原始监控已发布；CPU 精度优化与 3/6/12 个月小时汇总待评审，尚未发布
- 开发基线：`f798c8b`（发布版本 `v0.31.0` / `e829f6a`）
- 范围：本机宿主机、Docker 容器与三网固定节点历史趋势
- 当前变更：容器 CPU 区间采样、30 天窗口、长期小时汇总和全窗口资源优化（待发布）

## 1. 产品定位与入口

历史监控用于回答“过去一段时间服务器和容器是否出现资源异常”，不替代 Prometheus、
Grafana、日志平台或告警平台。

历史监控路由为 `/monitoring`，不占用左侧主导航位置；概览页“实时监控”区域提供“查看历史”入口，并可携带指标参数直接定位相应趋势图。页面包含：

- 宿主机四视图：CPU 与负载、内存、磁盘、网络与连接；磁盘可切换容量与读写 I/O，网络可切换流量与 TCP/UDP 连接；
- 容器四视图：CPU、内存、网络和块 I/O，PID 保留在实时摘要中；
- 三网延迟：同一视图展示电信、联通、移动在北京、上海、广州的九条线路，默认全部显示，用户可逐条显示或隐藏；
- 时间范围：最近 1 小时、6 小时、24 小时、7 天、30 天、3个月、6个月、12个月；30 天视图按 2 小时聚合，长期视图分别按 6、12、24 小时聚合；
- 数据状态：采样间隔、保留期、磁盘占用、最后成功采样、采样错误和容器截断数量。

页面使用仓库内轻量 SVG 折线图，不引入图表运行时、数据库或外部监控服务。每张图固定四个纵轴刻度，鼠标悬停时通过 SVG 屏幕坐标矩阵定位，只创建一条游标线和一个共享提示层，显示全部曲线时间范围内最近采样点的准确时间与数值；曲线保留真实采样点和峰值，不插值伪造中间数据。容器列表中不属于最新采样批次的序列以灰色“历史”状态展示，不将该状态解释成 Docker Engine 的实时运行结论。

## 2. 数据真源与沉淀位置

真实状态仍来自 Linux `/proc`、`/sys` 和 Docker Engine。历史文件只是有界观察记录，
不参与系统、Docker、应用或网站操作的成功判定。

数据由 `kejilion-agent` 写入：

```text
/var/lib/kejilion-panel/monitoring/
  metrics-YYYY-MM-DD.jsonl
  hourly-YYYY-MM.jsonl
```

目录权限为 `0700`，文件权限为 `0600`。文件按日分片，只使用 Agent 已有状态目录，
不新增 Panel 挂载和宿主机可写范围。

### 2.1 小时趋势汇总原型

30 天内继续以日分片原始记录作为查询来源。Agent 同时在有界内存中汇总当前小时，跨小时后把
上一小时写入月度 `hourly-YYYY-MM.jsonl`，用于 3、6、12 个月查询；当前尚未闭合的小时直接
从内存参与只读查询，不等待落盘。Agent 重启时最多扫描当日 4 MiB 原始分片，恢复当前小时，
不长期双写两份原始精度数据。

小时记录同时保留 CPU 峰值、CPU 样本数和按样本数加权的平均值；网络与磁盘 I/O 保留分钟/容器
采样间隔内计算出的最大速率，不再用相邻小时累计计数稀释短峰值；内存保留峰值，负载、连接数和
PID 保留峰值，累计网络与磁盘计数保留小时末最新值。三网延迟保留成功探测最大值，并累计成功/
失败次数，用于展示桶内可用率。跨 6/12/24 小时桶时 CPU 平均值继续按样本数加权，其他峰值继续
取最大，因此提升查询性能不会把已捕获峰值变成平均值。

为保证极限 32 容器下仍能写满 30 天，原始历史中的容器名称和镜像展示文本统一限制为 64 字节；
小时汇总保留 64 字节名称，不重复落盘镜像名，当前活动小时仍从内存返回完整受限镜像名，已停止的
长期历史容器显示“镜像信息未保留”。这只降低重复展示元数据精度，不改变 CPU、内存、网络、磁盘、
PID 或延迟指标。小时内容器 ID 最多暂存 64 个，落盘优先最近活跃的 32 个；跨月查询遇到更多历史
ID 时持续淘汰最旧序列，避免旧容器挤掉当前容器。

小时汇总不回填上线前已被清理的历史。汇总写入或清理失败只记录有界错误，原始采样继续保留；
回滚旧 Agent 时可忽略 `hourly-*` 文件，不影响既有 `metrics-*` 读取。

### 2.2 采样内容

宿主机每 1 分钟记录：

- CPU 使用率、核心数、1/5/15 分钟负载；
- 内存、Swap 使用量；
- 系统盘总量、使用量和使用率；
- Linux `/proc/diskstats` 中受支持整盘设备的累计读写扇区，并派生读写 B/s；
- 累计网络收发字节；
- TCP、UDP 连接数；
- 采集时间。

容器每 5 分钟记录：

- 容器 ID、名称和镜像名；
- CPU 使用率；使用 Docker 单次累计计数，并由相邻两轮容器采样的
  `cpu_usage.total_usage`、`system_cpu_usage` 差值计算区间平均值，不使用缺失
  `precpu_stats` 的累计比值；Agent 启动后的首轮采样和计数器回退记为 `0`，
  并遵循 Docker CLI 口径（多核容器可以超过 `100%`）；
- 内存使用量、限制和使用率；
- 累计网络收发字节；
- 累计块设备读写字节；
- PID 数。

宿主机磁盘 I/O 只累计 `sd*`、`vd*`、`xvd*`、`hd*`、`dasd*`、整盘 NVMe 和整盘 MMC 设备，不同时累计分区、loop、`dm-*` 与 `md*`，避免同一笔 I/O 被重复计算。无法可靠识别整盘设备时返回“不可用”，不猜测为 0。旧版历史记录没有磁盘字段时仍可读取，并从连续两个新记录开始计算速率，避免升级瞬间产生假峰值。

不记录环境变量、容器标签、执行命令、日志、文件、端口凭据、Token、密码或进程参数。

三网延迟每 5 分钟使用固定 IPv4 运营商节点执行一次有界网络往返探测：

| 运营商 | 北京 | 上海 | 广州 |
| --- | --- | --- | --- |
| 电信 | `219.141.136.10` | `202.96.209.5` | `202.96.128.86` |
| 联通 | `123.125.81.6` | `210.22.84.3` | `210.21.196.6` |
| 移动 | `221.179.155.161` | `211.136.112.50` | `211.136.192.6` |

目标只存在于 Agent 固定目录，API 不接受 IP、端口、域名或探测协议。每轮最多 3 个并发，
每个节点最长 1.5 秒；同时执行非特权 ICMP ping socket、TCP/53 与 UDP DNS 探测，以最先收到的
有效结果记录往返时间。全部超时或拒绝时记录为缺测值，不伪装成 `0 ms`。该实现不增加
`CAP_NET_RAW`，也不依赖宿主机 `ping` 命令。运营商归属以
[`gaoyifan/china-operator-ip`](https://github.com/gaoyifan/china-operator-ip) `master@4593b6c4d577b61e3c2189bcd06f1e4c24750b7d`
的公开 CIDR 数据于 2026-08-03 离线复核；运行时不下载该仓库或任何地址列表。

## 3. 资源边界

| 项目 | 固定边界 |
| --- | ---: |
| 宿主机采样间隔 | 60 秒 |
| 容器采样间隔 | 5 分钟 |
| 三网延迟采样间隔 | 5 分钟 |
| 三网探测目标 / 并发 | 固定 9 个 / 最多 3 个 |
| 单目标超时 | 1.5 秒 |
| 单轮容器数量 | 最多 32 个运行容器 |
| Docker Stats 并发 | 2 |
| 单轮容器采样总时长 | 30 秒 |
| 保留时间 | 完整滚动 30 天（最多涉及 31 个日分片） |
| 单日文件 | 最大 4 MiB |
| 历史目录 | 最大 128 MiB |
| 小时汇总保留时间 | 365 天（最多涉及 13 个月分片） |
| 单个月汇总文件 | 最大 16 MiB |
| 小时汇总目录额度 | 最大 128 MiB，与原始区合计最大 256 MiB |
| 单行 JSON | 最大 256 KiB |
| 查询输入扫描 | 最大 128 MiB，按日分片流式读取 |
| 查询输出点数 | 每条序列最多 720 点 |
| 查询容器序列 | 最多 32 条 |
| 同时历史查询 | 查询容量为 2；1h/6h/24h/7d 占 1，30d/3m/6m/12m 独占 2 |

达到边界时：

- 容器超过 32 个时按稳定名称顺序采样前 32 个，并返回遗漏数量；
- 单日或总目录达到上限时停止追加并报告状态，不挤占其他 Agent 状态；
- 读取到崩溃留下的半行、损坏行或未来协议记录时跳过该行，不把损坏解释为有效数据；
- 过期分片和超额最旧分片按固定文件名规则删除，不接受 API 传入路径。

## 4. API 契约

只增加已认证只读接口：

```text
GET /api/v1/monitoring/history?range=1h|6h|24h|7d|30d|3m|6m|12m
```

Panel 仅代理到 Agent Unix Socket：

```text
GET /v1/monitoring/history?range=...
```

响应包含：

- 固定配置和存储状态；
- 宿主机降采样序列；
- 容器元数据及降采样序列；
- 最后成功采样、最近错误、扫描字节数和损坏行数量。

未知参数、重复参数和非法范围返回 `422`。接口不接受任意路径、任意 URL、任意
Docker endpoint 或 Shell。

## 5. 性能与稳定性

- 采样在 Agent 单一后台 goroutine 中串行调度，页面关闭不影响采样；
- 宿主机采样不读取管理配置、不查询公网 IP，不产生外联；
- Docker 先执行一次容器列表请求，再对有界运行容器执行 Stats，不逐容器 Inspect；
- 三网延迟采样与 Docker Stats 并行，使用固定 UDP DNS 请求，不阻塞宿主机 `/proc` 采样；
- Stats 使用 2 个 worker、请求取消和 30 秒整轮超时；
- 历史查询按日期只读必要分片，并限制扫描量、并发和输出点数；30 天查询使用
  2 小时桶、最多返回 361 点（包含起止边界），并独占查询容量，避免两个长查询叠加瞬时 CPU 和内存；
- 3、6、12 个月只读取小时汇总，分别使用 6、12、24 小时桶，最多约 361、361、366 点，
  均独占两个查询槽，不扫描一年分钟级原始记录；
- 30 天内网络速率由相邻累计计数计算；小时汇总保留采样间隔峰值速率，计数回绕或容器重建时按 0 处理；
- 宿主机与容器统一使用 CPU 百分比、内存百分比、网络 B/s 和磁盘 I/O B/s；负载、连接数与磁盘容量是宿主机专属，PID 是容器专属；
- 前端在历史页只对时间戳做一次标准化，纵轴边界单次遍历计算，悬停点使用二分查找；切换磁盘或网络指标时复用同一张 SVG，不增加采样、API 请求或 Docker Engine 调用；
- Agent 重启后继续追加当日分片；损坏尾行可跳过，不需要数据库恢复或迁移；
- 容器列表先按最后采样时间保证当前运行或数据最新的容器在前，再按最新实际内存占用、CPU 使用率和名称排序；排序只处理最多 32 条已返回序列，不增加 Docker Stats 请求；
- 采样失败只记录有界错误摘要，不使 Agent、Panel 或现有业务接口退出。

## 6. 网络入侵安全记录

### 流量路径

```text
浏览器（已登录）
  -> Panel Session / CSRF 只读鉴权
  -> Agent Unix Socket + Bearer Token
  -> /proc、/sys、Docker Unix Socket
  -> 固定九个运营商 DNS 节点（UDP/53，每 5 分钟）
  -> Agent 私有历史目录
```

### 不可信输入

- 唯一输入为 `range` 枚举；
- 三网目标由 Agent 固定目录提供，不接受浏览器或 API 输入；
- Docker 响应和历史文件均按大小、类型和字段边界解析；
- 容器名称和镜像名作为纯文本 JSON 返回，由 Vue 自动转义。

### 权限与可写范围

- 不新增 TCP 监听、Linux capability、Panel 挂载或 Docker Socket 暴露；仅新增上表固定九个 UDP/53 只读探测目标；
- 只有 Agent 可写既有 `/var/lib/kejilion-panel`；
- 删除仅作用于由固定正则匹配的过期历史分片。

### 失败与恢复

- 网络断开不影响 Agent 本地采样；
- Docker 不可用时仍保存宿主机样本并记录 Docker 状态；
- 磁盘不足或只读文件系统时停止写入并保留旧数据；
- Agent 重启无需恢复内存状态，下一次采样继续写入；
- 从 7 天保留版本升级后不会伪造或恢复已清理数据，30 天窗口随新采样逐日补齐；
- 功能回滚只需恢复旧 Agent/Panel，历史 JSONL 可保留或人工删除，不影响其他业务。

- 固定目录、并发上限、超时缺测、降采样峰值和九线路最大响应均有 Go 自动测试；
- 32 容器上限与九线路同时采样的磁盘投影为 `3,194,208 bytes/day`；
- 7 天最大测试集响应为 `4,869,233 bytes`，低于既有 `8 MiB` Panel → Agent 响应边界；
- Windows amd64 基准中，7 天历史聚合为 `36.47 ms/op`、`8.04 MiB/op`；该数据仅用于本次变更回归，不作为不同硬件的性能承诺；
- Linux amd64/arm64 Agent 均完成无 CGO 交叉编译，监控包 Linux race test 通过；真实境内外线路可达率留待 L3 实机验收。

### 7.1 开发机基准记录

环境：Windows amd64、Go 1.26.5、Intel i5-12600KF；该结果用于发现回退，不作为低配服务器延迟承诺。

- 7 天、10,080 条纯主机记录流式读取并降采样：约 `41 ms/op`、`7.4 MiB/op`；
- 32 个容器按最大长度元数据持续采样的单日估算：`3,045,312` 字节，低于 `4 MiB` 硬上限；
- 32 个容器、7 天最坏响应构造：`4,013,707` 字节，低于 Panel→Agent `8 MiB` 响应上限；
- 前端独立懒加载产物：Monitoring 页面 JS gzip 约 `4.2 KiB`、CSS gzip 约 `1.5 KiB`。

实际生产开销仍受 `/proc`、Docker Engine 响应速度、容器数量和磁盘性能影响；30 秒整轮超时和固定并发是最终保护边界。

### 7.2 概览 A/B 与采样开销复核（2026-07-31）

测试提交：`6c0720b`。环境为 WSL2 Linux amd64、Go 1.26.5、Intel i5-12600KF。
Agent 固定在单个 CPU 上运行，并设置 `GOMAXPROCS=1`、`GOMEMLIMIT=128MiB`。A/B 使用
同一 Agent 二进制交替执行 3 轮，每轮并发 10、请求 `/v1/system/summary` 200 次；
开启组在负载期间触发首次真实宿主机采样，关闭组只令监控初始化失败，不修改概览实现。

| 指标 | 关闭采样 | 开启采样 | 差异 |
| --- | ---: | ---: | ---: |
| 概览核心接口 P50 | 169.43 ms | 169.80 ms | +0.22% |
| 概览核心接口 P95 | 181.60 ms | 182.64 ms | +0.57% |
| 概览核心接口 P99 | 186.26 ms | 188.06 ms | +0.96% |
| 200 请求平均完成时间 | 3.400 s | 3.410 s | +0.28% |
| Agent 平均峰值 RSS | 18,751 KiB | 18,935 KiB | +184 KiB |
| HTTP 错误 | 0 | 0 | 无变化 |
| 首个历史样本 | 0 | 249 B；文件系统写入 4 KiB | 有界追加 |

补充微基准均限制为单核：

| 场景 | 平均耗时 | 临时分配 |
| --- | ---: | ---: |
| 7 天 10,080 条主机记录查询并降采样 | 28.06 ms/op | 7.36 MiB/op |
| 宿主机记录编码、追加和清理（模拟采集源） | 10.15 µs/op | 1.91 KiB/op |
| 32 容器记录编码、追加和清理（模拟采集源） | 28.04 µs/op | 13.99 KiB/op |
| 32 容器 Docker HTTP 响应读取与解析（本机模拟 Engine） | 4.77 ms/op | 300.89 KiB/op |

结论：在本轮可控环境中，开启宿主机历史采样对概览 P95 的影响低于 1%，峰值 RSS
增加约 184 KiB，不构成当前性能瓶颈。历史页面查询仍是主要瞬时内存来源，但已有查询并发、
扫描量和输出点数上限。

限制：本轮没有可用的真实 Docker daemon，因此容器微基准覆盖了 KPanel 的并发 HTTP、
JSON 解析、记录编码和写盘，不包含 Docker daemon 生成 Stats 的实际耗时；`GOMEMLIMIT`
也不是硬 cgroup 内存限制。扩大采样频率、容器上限、保留期或迁移存储前，仍须在
`1 vCPU / 1 GiB` 的真实 Linux + Docker 主机复跑 60 分钟以上 A/B。

### 7.3 磁盘 I/O 与界面改版性能复核（2026-07-31）

同机、同 Go 版本分别对回滚点 `0f3e474` 和本轮代码运行 5 次 7 天历史查询基准：
