# 应用市场生态对齐

## 目录与事实来源

- Agent 每五分钟从固定的 `https://app.kejilion.sh/` 读取并严格校验
  `window.__APPS__`，只动态替换第三方展示目录；115 个脚本内置应用和执行适配器
  始终来自随版本审计的本地快照。
- 当前官方目录包含 146 个应用：115 个 `kejilion.sh` 内置应用、31 个第三方应用、7 个分类。
- 上游不可用或字段、分类、数量、URL、ID、重复项校验失败时，使用最近一次已校验目录；
  Agent 重启后仍可回退随版本发布的内置快照，应用市场不会因断网不可用。
- 已随版本发布的图标位于 `web/public/app-icons`，运行时不远程热链；新入驻但尚未随
  KPanel 版本发布图标的应用使用本地通用图标。
- `scripts/audit-kejilion-apps.mjs` 从指定的 `kejilion.sh` 提取 115 个内置应用的主容器、镜像、
  默认端口和管理类型，生成 `internal/appmarket/legacy-apps.json`。
- Docker Engine 是安装与运行状态的事实来源；`/home/docker/appno.txt` 只作为脚本兼容标记。
  只有标记、没有容器时显示“待核对”，不会伪装成正常运行。

同步随版本发布的回退目录和本地图标：

```bash
node scripts/sync-app-market.mjs
```

重新审计脚本映射：

```bash
node scripts/audit-kejilion-apps.mjs /path/to/kejilion.sh internal/appmarket/legacy-apps.json
```

两条命令都有严格的数量、字段、URL、文件类型、大小和重复项校验。上游内置应用或分类结构发生
变化时，同步会失败，必须先人工复核。运行时远程目录只提供应用标识与展示元数据；安装执行仍由
本机已更新且支持 KPanel 非交互协议的 `kejilion.sh` 解析固定应用标识，KPanel 不接收远程命令行。

## 功能矩阵

| 功能 | 全部目录应用 | `kejilion.sh` 标准应用 | 声明式适配应用 |
| --- | --- | --- | --- |
| 搜索、分类、来源与状态筛选 | 是 | 是 | 是 |
| 脚本安装标记、容器状态、端口和镜像 | 视可用产物 | 是 | 是 |
| 后台安装与进度 | 需要可用适配器 | 是 | 是 |
| 启动、停止、重启 | 已识别容器按实时状态开放 | 同左 | 是 |
| 镜像更新检查 | 有镜像标签和仓库摘要时 | 同左 | 是 |
| 添加域名 | 有可识别 TCP 端口时 | 同左 | 是 |
| 删除域名 | 按实际反向代理资源 ID | 同左 | 同左 |
| 阻止/放行 IP+端口 | 需要脚本管理协议或可识别端口 | 脚本协议可用时 | 是 |
| 更新、卸载 | 需要脚本管理协议或声明式适配器 | 脚本协议可用时 | 是 |

当前审计快照中，99 个采用 `docker_app`/`docker_app_plus` 的内置应用，以及官方目录中由
`docker_app_plus` 提供配置的第三方应用，可以直接从 KPanel 发起后台安装。使用面板安装器或其他
专属交互流程的应用继续显示“需要专属配置向导”，不会伪装成可无人值守安装。

首批声明式适配应用：

- LibreSpeed：`speedtest`，默认 `8028 -> 8080/tcp`
- IT-Tools：`it-tools`，默认 `8064 -> 80/tcp`
- DOS 游戏：`dosgame`，默认 `8076 -> 262/tcp`

这三项与脚本当前镜像、容器名和端口一致，是首批内置声明式适配器。脚本或管理员后续修改
镜像、挂载、特权、网络、Capability 或设备不会取消其管理权限；更新与访问模式切换只要求
仍能识别该应用约定的端口。

## 双向兼容

KPanel 安装成功后原子更新：

- `/home/docker/appno.txt`
- `/home/docker/<container>_port.conf`

因此脚本菜单会显示已安装，脚本读取端口时也能获得相同值。写兼容文件失败时，KPanel 会删除刚创建
的容器并报告已回滚；容器回滚也失败时进入“需要人工检查”，不伪报成功。

脚本安装或修改应用后，KPanel 下一次请求会重新读取 Docker 与兼容文件。应用配置、marker、
容器名、Compose label 与工作目录共同用于发现；任何单一 KPanel 专属标识都不构成管理授权。

## 后台安装、更新与卸载事务

应用安装请求先持久化到 `/var/lib/kejilion-panel/app-jobs`，再返回任务 ID。页面每两秒读取一次
进度，离开应用市场或刷新浏览器不会中断任务；任务详情只向已登录会话返回最近的受限日志。
首版为避免多个 Compose 安装器争用端口、软件包管理器和 `/home/docker/appno.txt`，同一时间只
执行一个应用安装任务。

声明式安装器接受：

- 固定应用 ID、容器名、镜像和容器端口；
- 用户选择的 `1-65535` 宿主机端口；
- `direct` 或 `domain_only` 两种访问模式。

标准脚本安装器由独立的 systemd 临时服务在后台执行，只接受经过正则校验的数字编号或应用 token，
动作固定为 `install`，可选端口限制为 `1-65535` 并在安装前检查占用。它通过
`KJ_APP_NONINTERACTIVE=1 KJ_APP_ACTION=install` 调用本机 `kejilion.sh app <selector>`，
直接复用脚本的 Docker/Compose、数据目录、默认凭据和兼容标记业务，不模拟终端输入。脚本未更新、
文件可被非 root 用户修改、用户尚未在终端运行 `k` 接受许可协议、系统没有 systemd，或应用仍要求
专属交互配置时，安装能力保持禁用。KPanel 不会代表用户自动接受脚本许可协议。

后台任务状态文件和日志权限为 `0600`；Web 容器没有 Docker Socket，也不能直接执行脚本。

更新先拉取新镜像，再核对 `resourceVersion` 和应用约定端口。重建失败时使用原镜像 ID、端口、
访问模式、标签和运行状态恢复旧容器。卸载按发现到的主容器执行，不要求镜像、挂载、特权参数或
KPanel label 保持不变；共享镜像、Docker prune 和应用数据目录仍由对应脚本业务决定。

## 域名与直接访问

添加域名调用网站管理的固定反向代理事务，目标只能是 `http://127.0.0.1:<已识别端口>`。Nginx
配置必须通过 `nginx -t`，然后才 reload；失败时恢复原配置。

删除域名按实际反向代理资源 ID 和资源版本执行，并且只移除 Nginx 入口；静态站、PHP 站和
数据目录不通过应用域名入口删除。

标准脚本应用通过 `kejilion.sh` 非交互管理协议执行原生阻止/放行流程。声明式应用以当前容器
运行信息重建端口绑定，把宿主机监听地址在公网地址与回环地址之间切换；宿主机 Nginx 仍可通过
回环地址访问。

## 继续扩展适配器

新增可写应用前必须逐项确认：

1. 当前 `kejilion.sh` 的镜像、端口、环境变量、挂载、网络与重启策略。
2. 数据目录兼容、升级迁移、密钥处理和失败回滚方式。
3. 远程目录只提供展示元数据；执行参数必须来自本机脚本或随版本发布的结构化适配器。
4. 安装、更新、卸载、端口冲突、断网、Agent 重启和外部并发修改测试全部通过。
5. 目录和运行规格分离：`app.kejilion.sh` 只提供展示元数据，不能注入命令；容器是否带
   特权或自定义配置不影响管理员后续管理权限。
