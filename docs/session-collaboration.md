# KPanel 会话协作

## 使用方式

以后只需在置顶的 `KPanel · 协调中心` 中描述目标。协调中心会先查找可复用的 KPanel
任务；领域匹配时继续旧任务，否则创建新任务，并在结果返回后统一验收和汇报。

建议用一句话同时说明目标和验收标准，例如：

```text
检查应用市场安装终端卡住的问题，修复后跑相关 Go 测试，不要部署。
```

## 会话分工

| 标题 | 职责 |
| --- | --- |
| `KPanel · 协调中心` | 接收需求、路由、跟踪、验收、汇总 |
| `KPanel · 分析 · <领域>` | 只读排查、设计和风险分析 |
| `KPanel · 开发 · <领域>` | 在明确文件范围内实现修改 |
| `KPanel · 验证 · <领域>` | 独立运行测试和复核结果 |

会话 ID 不写入项目。标题、项目路径和任务状态共同构成动态索引，因此旧任务被归档或
迁移后仍可重新发现。

## 并发与工作树

当前 Codex 保存的项目是父目录 `C:\GitHub`，而不是独立的
`C:\GitHub\kejilion-panel` Git 项目。因此：

- 新建会话和复用会话均可正常工作；
- 共享目录中的只读分析可以并发；
- 两个会话不能同时修改同一工作树；
- 若要安全并行开发，应先在 Codex 中把 `C:\GitHub\kejilion-panel` 添加为独立项目，
  之后新开发任务即可默认使用 Git worktree。

## 决策顺序

1. 读取本项目规则和当前 Git 状态。
2. 查找同领域的 KPanel 旧任务。
3. 无冲突时继续旧任务；没有合适任务时创建新任务。
4. 等待子任务回传，协调中心本地复核。
5. 向用户统一说明完成项、修改、验证、风险和知识沉淀。

可复用的完整执行步骤见
`.codex-workflows/session-collaboration.workflow.yaml`。
